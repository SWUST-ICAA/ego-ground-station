# 独立单机地面站设计

用户确认：三架互不通信；复用原规划器到点、返回起飞点、自动降落。没有 GNSS 时米制任务可执行，经纬度输入不可用。

PyQt5 界面通过每机 SSH 管理现有 Docker。机上轻量 Python ROS 任务进程通过 Unix socket 接收 JSON，监测状态并执行任务，断开地面站不丢失任务。没有新网络监听端口，不更改规划器算法。启动程序不解锁；一键任务才启动控制器并请求解锁。关闭程序必须有新鲜的未解锁、已着陆证据。拒绝正在执行时覆盖任务；请求有唯一 ID 防重复。

任务：预检、捕获本机起飞点、控制器起飞、稳定到高度、逐个目标、返回起飞点、AUTO.LAND、确认着陆和锁定。返航继续走 /move_base_simple/goal，维持 1.5m 和初始 yaw；不使用 RTL。位置、速度和持续停留一起判定到达。手动模式接管后不自动抢回 OFFBOARD；异常、超时展示原因。断开地面站后已接受任务继续在机上运行。

旧数据源为 /mavros/global_position/global (NavSatFix)，辅以 /mavros/global_position/compass_hdg 和本机 local_position/odom。WGS84 转局部 ENU，再按本机姿态/罗盘转换到本机 map，锚点不跨飞机共享。新鲜、有效、同步的定位数据才允许地理输入，已经解析的米制任务不依赖后续 GNSS。绝不将无效经纬度替代为 (0,0)。

界面包含三架可选卡片/状态表、逐机航点列表（米制绝对 map 或经纬度 WGS84）、批量启动/停止、执行任务、返航、就地降落、事件日志和各机局部轨迹预览。局部轨迹分别展示，不画成共同地图。连接密码仅保存在本机未跟踪配置。模拟演示无需连接飞机。

当前规划器固定目标 z=1.5，控制器起飞高度相对起飞点 +1.5；起飞点 z 偏离零超过 0.15m 则拒绝任务并说明原因，避免静默改变现有地图/规划器参数。目标需位于现有 [-50,50]x[-25,25] 地图内，边界预留 1.3m。

验证：纯任务状态机/地理转换单元验证、隔离 ROS 适配验证、Qt 无显示交互和截图、三机只读状态验证。绝不在真机验证解锁/起飞/导航命令。按用户要求最终移除临时测试文件。
